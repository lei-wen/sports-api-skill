# 红火体育赛事数据

作为红火体育赛事数据接口的统一入口。根据用户意图选择一个最匹配的子 Skill，再依照该子 Skill 完成参数确认与请求。不要同时加载全部子 Skill。

## 路由

当接口目标尚未唯一确定时，读取 [references/routes.md](references/routes.md)，根据用户的领域、对象和动作选择子 Skill。

以下说法容易歧义，必须先澄清：

- “赛程”：可能是竞猜赛程、世界杯赛程、女篮世界杯赛程或某支球队赛程。
- “详情”：可能是推荐详情、指数详情、球队资料或比赛详情数据。
- “榜单”：可能是世界杯/女篮世界杯的球队榜或球员榜。
- “赛果”：可能按日期/期次查询，也可能按比赛 ID 查询。

若用户只是询问支持哪些数据，不调用接口；按 `routes.md` 的八个分组给出简短能力列表。

## 下发到子 Skill

确定路由后：

1. 在本 Skill 目录内定位 `skills/<child-skill>/SKILL.md`。
2. 完整读取选定子 Skill 的 `SKILL.md`，把它作为本次接口调用的权威说明。
3. 只使用该子 Skill 规定的 URL、请求方式、请求体、参数名、枚举值和响应处理方式。
4. 若子 Skill 不存在或不可读，报告具体名称与预期相对路径并停止；不要改用相似接口。

## 参数补问

从用户原始请求提取参数，并与子 Skill 的“请求参数”核对。

- 参数齐全且合法：直接请求，不重复确认。
- 缺少必填参数：先补问，收到答案后再请求。
- 多个必填参数缺失：合并成一次简短问题，用编号列表逐项列出。
- 枚举参数缺失或值无效：列出合法选项及含义，让用户选择。
- 可选参数：只有它会显著改变结果范围时才询问；否则采用文档默认值或省略。
- 用户使用自然语言给出明确值时，直接转换为接口枚举。例如“竞彩足球”映射为 `jc_type=jczq`。
- 不猜测比赛 ID、球队 ID、赛季 ID、推荐内容 ID、公司 ID 或分页大小。

提问示例：

```text
需要补充以下参数：
1. 比赛 ID（match_id2）
2. 竞猜类型（lottery_id）：90 竞彩足球 / 91 竞彩篮球 / 10 足彩 / 45 北京单场
```

对于“赛程”类歧义，可询问：

```text
你要查询哪类赛程？
1. 当前在售竞猜赛程
2. 世界杯赛程
3. 女篮世界杯赛程
4. 指定球队赛程
```

## 凭据与调用

子 Skill 使用以下本地环境变量：

- `SPORTS_API_APP_ID`
- `SPORTS_API_APP_SECRET`
- `SPORTS_API_BASE_URL`（可选）

只检查凭据是否存在，绝不回显其值。凭据缺失时告诉用户在本地配置，不要要求用户把密钥发到聊天中。

接口调用属于外部读取。调用后先检查 HTTP 状态和业务 `errcode`，成功时按用户问题整理结果；失败时报告错误码、消息和可执行的修正建议。未经用户要求，不把完整原始响应保存为长期文件。

## 文档缺口

`sports-api-bull-pick-list` 和 `sports-api-bull-pick-detail` 对应的源文档只有标题，没有 URL 与参数。路由到它们时说明缺口并请求更新的接口定义，禁止猜测或复用专家推荐接口。
